A1932 CLASSROOM LIVE TRANSLATOR
Compact C++20 Architecture and Per-File Token Roadmap
Target: MacBook Air A1932, Core m3-8210Y, UHD 617, Ubuntu 24.04
Primary objective: live English classroom speech recognition and Chinese translation while preserving CPU responsiveness for OneNote.

Document version: 0.1
Architecture style: small modular monolith, bounded queues, parallel pipeline
Implementation language: C++20

======================================================================
0. INTERPRETATION OF "TOKEN ROADMAP"
======================================================================

In this document, "token roadmap" means the recommended AI coding budget and
prompting order for each source file. It is not the number of language-model
tokens processed by Whisper.

The budget is intentionally small. Each AI task should generate one narrow,
reviewable file or one tightly coupled header/source pair. Never ask an AI to
generate the entire repository in one prompt.

Recommended total initial AI budget:

  Skeleton and interfaces:          8,000 to 11,000 tokens
  Audio, VAD, and buffering:       10,000 to 14,000 tokens
  Whisper/Vulkan integration:       8,000 to 12,000 tokens
  Translation and output:           8,000 to 12,000 tokens
  Application wiring and tests:     9,000 to 13,000 tokens
  Review, fixes, and optimization:  10,000 to 16,000 tokens

  Total expected range:             53,000 to 78,000 tokens

This can be reduced by implementing the MVP without local Chinese translation.
An English-caption-only MVP needs approximately 35,000 to 50,000 tokens.

======================================================================
1. SYSTEM GOALS
======================================================================

Hard requirements:

1. Capture the built-in microphone through PipeWire.
2. Convert captured audio to mono, 16 kHz, signed 32-bit float PCM.
3. Detect speech and avoid running inference during silence.
4. Run whisper.cpp with its GGML Vulkan backend on UHD 617.
5. Keep CPU use bounded so OneNote remains responsive.
6. Emit timestamped English text and optional Chinese translation.
7. Write human-readable lines to stdout and an optional named pipe.
8. Save a transcript for later summarization.
9. Recover cleanly from microphone disconnects and output-reader disconnects.
10. Operate as one executable without Python, Electron, Qt, or a database.

Non-goals for version 1:

1. Cross-platform support.
2. Multiple simultaneous microphones.
3. A graphical interface.
4. Speaker diarization.
5. Word-level karaoke highlighting.
6. Network accounts or cloud synchronization.
7. A plugin system.
8. Runtime model conversion.
9. Perfect simultaneous interpretation.
10. Supporting arbitrary Linux distributions.

Central design rule:

  The audio callback must never block, allocate memory, call Whisper, translate,
  write a file, print to a terminal, or wait on a mutex.

======================================================================
2. TOP-LEVEL PIPELINE
======================================================================

  PipeWire microphone
          |
          v
  AudioCapture callback
          |
          v
  Preallocated SPSC AudioRing
          |
          v
  AudioWorker: channel conversion/resampling/DC cleanup
          |
          v
  VAD segmenter with pre-roll and hangover
          |
          v
  Bounded SpeechQueue
          |
          v
  WhisperWorker using GGML Vulkan
          |
          v
  Bounded TranscriptQueue
          |                         \
          v                          v
  TranslationWorker             TranscriptWriter
          |                          |
          v                          v
  Bounded OutputQueue           session.txt
          |
          v
  OutputWorker
      |       |       |
      v       v       v
   stdout   FIFO    optional ncurses view later

Backpressure policy:

1. AudioRing full: drop the oldest audio block and increment a counter.
2. SpeechQueue full: reject the oldest unprocessed segment, never block capture.
3. TranscriptQueue full: preserve English transcript on disk first; translation
   may be skipped.
4. FIFO has no reader: continue stdout and file output; retry FIFO later.
5. UI/output slow: coalesce partial captions and preserve final captions.

======================================================================
3. THREAD MODEL
======================================================================

Thread A: PipeWire event loop / audio callback
- Highest practical priority, but do not use dangerous real-time settings first.
- Copies frames into AudioRing only.
- Performs no heap allocation after startup.

Thread B: Audio and VAD worker
- Reads blocks from AudioRing.
- Performs lightweight format normalization and VAD.
- Builds speech segments with pre-roll and hangover.
- Pushes completed segments into SpeechQueue.

Thread C: Whisper worker
- Owns the whisper_context.
- Performs one inference at a time.
- Uses the Vulkan-enabled GGML build.
- Publishes partial/final English transcript events.

Thread D: Translation worker
- Optional and lower priority than Whisper.
- Consumes finalized English sentences only.
- May initially use an external CLI adapter or a compact translation library.
- Must be possible to disable at compile time and runtime.

Thread E: Output and transcript worker
- Owns stdout, FIFO, and transcript file descriptors.
- Formats timestamps and output records.
- Never blocks another stage.

Main thread
- Parses configuration.
- Creates all bounded queues and workers.
- Handles SIGINT/SIGTERM through a safe stop flag.
- Starts and joins workers in deterministic order.

Recommended Linux scheduling policy for version 1:

- Audio callback/event loop: normal scheduling, nice -2 only if needed.
- Whisper worker: normal priority.
- Translation worker: nice +5 or idle scheduling if it competes with OneNote.
- Output worker: normal priority.

Do not enable SCHED_FIFO until the program is proven stable. A bug in a real-time
thread can freeze the desktop.

======================================================================
5. CORE DATA TYPES AND OWNERSHIP
======================================================================

AudioBlock
- Fixed-capacity array of float samples.
- frame_count, channel_count, sample_rate, monotonic timestamp.
- No owning heap pointer.

SpeechSegment
- std::vector<float> owned by the segment after leaving the real-time path.
- start/end timestamps.
- sequence number.
- VAD confidence or speech-frame ratio.

TranscriptEvent
- sequence number.
- start/end timestamps.
- English UTF-8 text.
- final/partial flag.
- inference duration and real-time factor.

TranslatedEvent
- Original TranscriptEvent metadata.
- English text.
- Chinese UTF-8 text, possibly empty when translation is disabled or skipped.
- translation status enum.

MetricsSnapshot
- dropped audio blocks.
- queued speech segments.
- last inference duration.
- rolling real-time factor.
- translation backlog.
- total finalized utterances.

Ownership rules:

1. AudioCapture owns the PipeWire objects.
2. Application owns all workers and shared queues.
3. WhisperEngine exclusively owns whisper_context.
4. Translator exclusively owns its translation backend.
5. OutputSink exclusively owns FIFO/stdout state.
6. TranscriptWriter exclusively owns the transcript file.
7. No global mutable objects.
8. std::stop_token controls cooperative shutdown.

----------------------------------------------------------------------
6.7 include/classroom/vad_segmenter.hpp + src/vad_segmenter.cpp
----------------------------------------------------------------------

Purpose:
- Convert normalized audio frames into bounded speech segments.

Dependencies:
- WebRTC VAD, types.hpp, bounded_queue.hpp.

Algorithm:
- Convert float frames to int16 only at the WebRTC VAD boundary.
- Use supported 10/20/30 ms frames; start with 20 ms.
- Maintain approximately 300 ms pre-roll.
- Start speech after a small number of positive frames.
- End speech after approximately 500 to 800 ms hangover silence.
- Force-cut segments around 12 to 18 seconds.
- Add small overlap when force-cutting to avoid lost words.

Approximate size:
- Header 100 lines; source 280 to 380 lines.

AI budget:
- 3,500 to 5,000 tokens.

Prompt roadmap:
1. Ask for the segment state machine in prose/pseudocode.
2. Review edge cases: short cough, long lecture sentence, silence, force cut.
3. Generate the header and state enum.
4. Generate source from the approved state machine.
5. Generate deterministic tests with synthetic VAD decisions.

Completion test:
- No segment is shorter than configured minimum unless flushing at shutdown.
- No segment exceeds maximum plus overlap tolerance.
- Pre-roll is included exactly once.

6.13 include/classroom/application.hpp + src/application.cpp
----------------------------------------------------------------------

Purpose:
- Wire components, queues, lifecycle, and shutdown together.

Dependencies:
- Every subsystem interface, but no low-level PipeWire or Whisper logic.

Startup order:
1. Parse/validate config.
2. Initialize metrics and bounded queues.
3. Initialize Whisper and translation backend before microphone capture.
4. Initialize output and transcript.
5. Start output, translation, Whisper, VAD/audio workers.
6. Start capture last.

Shutdown order:
1. Stop capture first.
2. Flush audio/VAD into a final segment.
3. Close SpeechQueue.
4. Let Whisper finish or obey configured grace period.
5. Close TranscriptQueue and translation queue.
6. Flush outputs/transcript.
7. Join all jthreads.

Approximate size:
- Header 90 lines; source 280 to 380 lines.

AI budget:
- 3,000 to 4,500 tokens.

Prompt roadmap:
1. Give the AI only interfaces and required startup/shutdown order.
2. Generate ownership fields and constructor.
3. Generate run() and request_stop().
4. Conduct a shutdown/deadlock review in a separate prompt.

Completion test:
- Ctrl+C exits cleanly at every startup stage.
- Failure to initialize one component tears down all earlier components.

- OneNote typing remains responsive under representative load.

======================================================================
10. PERFORMANCE AND POWER TEST PLAN
======================================================================

Measure four builds/modes:

A. CPU-only Whisper, one thread.
B. CPU-only Whisper, two threads.
C. Vulkan Whisper, one CPU helper thread.
D. Vulkan Whisper, two CPU helper threads.

For each mode record:
- Mean and 95th percentile real-time factor.
- End-of-speech to final-caption latency.
- Whole-process CPU percentage.
- GPU render/compute utilization from intel_gpu_top.
- Package power and temperature.
- Dropped audio/segments.
- Subjective OneNote typing and scrolling responsiveness.

Representative test:
1. Play a 20-minute lecture through a nearby speaker at realistic volume.
2. Type continuously in OneNote.
3. Keep the same power profile and screen brightness.
4. Repeat each mode at least twice.
5. Prefer the lowest CPU mode that stays below real-time factor 1.0 with margin.

Target thresholds:
- Average real-time factor <= 0.75.
- 95th percentile final-caption latency <= 4 seconds.
- No unbounded backlog.
- No noticeable OneNote input lag.
- No thermal collapse after 20 minutes.

======================================================================
11. FAILURE HANDLING
======================================================================

Microphone unavailable:
- Retry with bounded backoff and show one concise status message.

Audio callback overrun:
- Drop oldest block, increment counter, continue.

VAD produces a very long segment:
- Force-cut with overlap.

Whisper slower than real time:
- Drop stale unprocessed segment before dropping current speech.
- Disable translation automatically if configured.
- Emit an overload warning no more than once per interval.

Vulkan initialization fails:
- Either fail fast or use an explicit allow_cpu_fallback option.
- Never silently switch to CPU and ruin OneNote responsiveness.

Translation fails:
- Emit English only and mark translation status.

FIFO has no reader:
- Continue stdout and transcript; retry nonblocking.

Disk write fails:
- Continue live captions and report the error once.

Shutdown during inference:
- Allow current short segment to finish within a grace period; then exit.

======================================================================
12. AI CODING RULES FOR A SMALL CODE BASE
======================================================================

Every AI prompt should include:

1. Exact file path.
2. Exact responsibility and forbidden responsibilities.
3. Existing public interfaces pasted verbatim.
4. Thread ownership and blocking policy.
5. Allocation policy.
6. Error-handling policy.
7. Maximum approximate line count.
8. Required tests.
9. Request for complete compilable code, not pseudocode.

Never ask an AI to:

- Invent whisper.cpp API calls without providing the installed whisper.h.
- Generate more than one complex subsystem at once.
- Replace bounded queues with unlimited std::queue usage.
- log from the PipeWire callback.
- perform translation in the Whisper thread.
- add a framework to solve a small local problem.
- silently add cross-platform abstraction.
- use detached threads.
- use system() for helper execution.
- catch all exceptions and ignore them.

Recommended per-file AI loop:

Step 1: Ask for interface/invariants only, 300 to 600 tokens.
Step 2: Human checks ownership and dependency direction.
Step 3: Ask for implementation, 1,000 to 3,000 tokens.
Step 4: Compile immediately.
Step 5: Ask AI to fix only the exact compiler errors, with the error text.
Step 6: Ask for focused tests, 800 to 2,000 tokens.
Step 7: Run sanitizers.
Step 8: Ask for a concurrency/lifetime audit, 500 to 1,000 tokens.
Step 9: Freeze the public interface before parallel branches depend on it.

======================================================================
13. DEPENDENCY DIRECTION
======================================================================

Allowed:

  main -> application
  application -> subsystem interfaces
  audio_capture -> audio_ring, metrics, PipeWire
  audio_processor -> types
  vad_segmenter -> types, WebRTC VAD, speech queue
  whisper_engine -> types, whisper.cpp, transcript queue
  translator -> types, translation queue
  output/transcript -> types

Forbidden:

  audio_capture -> Whisper
  Whisper -> PipeWire
  translator -> PipeWire
  output -> Whisper internals
  shared headers -> PipeWire/Vulkan implementation details
  any subsystem -> Application

This one-way dependency graph is what allows files to be generated and reviewed
in parallel without constant merge conflicts.

======================================================================
15. DEFINITION OF DONE FOR VERSION 1
======================================================================

Version 1 is done when:

- One command starts the program.
- The program confirms the selected microphone, model, and UHD 617 Vulkan device.
- English captions appear from live classroom speech.
- Optional Chinese lines appear without blocking English recognition.
- OneNote remains responsive during a 60-minute test.
- The process does not grow memory continuously.
- Ctrl+C exits cleanly.
- A missing FIFO reader does not crash the program.
- A timestamped transcript is saved.
- Overload causes bounded, visible degradation rather than unlimited delay.
- The first-party code remains small enough for one person and a modest AI to
  understand file by file.

======================================================================
16. FINAL RECOMMENDATION
======================================================================

Build a modular monolith, not microservices and not one giant source file.
Use five worker roles but only a few bounded queues. Keep the real-time audio
callback extremely small. Give Vulkan Whisper exclusive ownership in one worker.
Treat Chinese translation as optional lower-priority work. Preserve English and
responsiveness before translation completeness.

The best first deliverable is not the complete translator. It is this narrow,
measurable chain:

  PipeWire -> AudioRing -> VAD -> whisper.cpp Vulkan -> stdout

Once that chain runs below real time without disturbing OneNote, add transcript
persistence, FIFO output, and finally Chinese translation.
